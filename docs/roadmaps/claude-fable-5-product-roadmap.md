# Takio Product-Delivery Roadmap

> Generated by Claude Code using `claude-fable-5` on 2026-07-18 from the adjacent saved planning prompt. This is intentionally strategic and abstract.

## Product Pillars

- **Local-first, no lock-in** — the library lives in plain, inspectable storage on the user's machine; every feature works offline and no capability is gated on a service.
- **One domain, many surfaces** — desktop app, CLI, and future device agents are thin shells over a single shared domain package; behavior never forks between surfaces.
- **Agent-native by design** — the CLI is a first-class product for AI agents and scripts: machine-readable output, deterministic exit codes, idempotent commands, stable contracts.
- **Reliable long-running work** — conversions and syncs run through a persistent job queue that survives crashes and restarts; the user always sees truthful job state.
- **Lightweight over exhaustive** — deliberately smaller than Calibre: fast startup, modern UX, a curated set of formats done well rather than everything done poorly.

## Delivery Horizons

### Horizon 1 — Foundation

- **Outcomes:** A stable domain model and library store both surfaces can build on; Codex can work against a fixed contract.
- **Major capabilities:** Shared domain package; local library storage with import and metadata editing; minimal CLI with JSON output; desktop shell browsing the same library; CI, typecheck, and test harness gating every merge.
- **Non-goals:** Conversion, job queue, networking, device sync, adapters, UI polish.
- **Exit criteria:** CLI and desktop operate on the same library with identical results; domain contracts are versioned and test-covered; a green pipeline is required and sufficient to merge.

### Horizon 2 — Local Conversion

- **Outcomes:** Takio converts books locally and reliably; long-running work is durable and observable.
- **Major capabilities:** Converter adapter contract with first local adapters behind it; persistent job queue with enqueue, progress, retry, cancellation, and restart behavior; conversion from both CLI and desktop with consistent semantics; format detection and failure reporting.
- **Non-goals:** Remote execution, distributed devices, adapter marketplace, exotic formats, batch-orchestration UX.
- **Exit criteria:** A conversion survives a process crash and resumes or fails cleanly with truthful state; the same conversion via CLI and desktop yields identical artifacts; the adapter contract is documented so a new adapter needs no core changes.

### Horizon 3 — Unified Experience

- **Outcomes:** The desktop app becomes a coherent daily-driver workspace; the CLI becomes a dependable automation substrate.
- **Major capabilities:** Full library UX; job-center UI over the queue; CLI ergonomics for agents including scriptable pipelines and stable schemas; shared config and error model; first-run and empty-state experience.
- **Non-goals:** Multi-user features, cloud accounts, remote devices, theming/extensibility platform.
- **Exit criteria:** A user manages a real library end-to-end without touching the filesystem manually; an agent scripts the full import → convert → verify flow unattended; UX review of real flows passes on core journeys.

### Horizon 4 — Distributed Devices

- **Outcomes:** Trusted remote device agents extend the local library with send-to-device and remote conversion while preserving local-first behavior.
- **Major capabilities:** Authenticated device-agent protocol with pairing, mutual authentication, and revocation; routed jobs; device management in CLI and desktop; conflict-safe transfer semantics.
- **Non-goals:** Cloud-hosted sync service, public multi-tenant server, real-time collaboration.
- **Exit criteria:** A device can be paired, used, and revoked with no credential persisting past revocation; remote jobs report the same truthful lifecycle as local ones; the system degrades gracefully to fully local when no devices are reachable; security review of the auth/transport model passes.

### Horizon 5 — Release Readiness

- **Outcomes:** Takio is installable, updatable, and trustworthy for the public.
- **Major capabilities:** Signed and notarized desktop builds; CLI distribution including agent install paths; auto-update with rollback; library-data migration guarantees; human and agent documentation; explicit telemetry policy.
- **Non-goals:** New feature surface, growth features, plugin ecosystem launch.
- **Exit criteria:** Fresh-machine install → use → update → rollback works on every supported platform; library data survives upgrade round-trips; a release/rollback runbook exists and has been exercised.

## Cross-Cutting Quality and Security Principles

- **Contracts before consumers:** Domain and adapter contracts are versioned, tested, and changed deliberately.
- **Truthful state everywhere:** Jobs, syncs, and errors report what actually happened; no silent failure or optimistic status.
- **Trust boundaries are validated:** File imports, format parsers, CLI input, and device messages are untrusted input.
- **Least privilege by default:** Device agents authenticate mutually, credentials are revocable, and the desktop app requests only the OS capabilities it uses.
- **Local data is sacred:** No operation may corrupt or orphan library data; destructive actions are explicit and upgrades are migration-tested.
- **Simplicity as a gate:** Speculative abstraction is a review finding; every generalization needs a second concrete use.
- **Evidence over assertion:** Nothing is complete without a runnable check that fails when behavior breaks; skipped checks are surfaced, never hidden.
